# v4.1 implementation workflow

## Scope reading

One v4.1.0 release covering all 15 brief items (8 P0, 6 P1, 3 P2). Six phases, ~33 tasks, one CHANGELOG entry, one version bump via `scripts/bump-version.js`, one smoke chain, one tag. Not split across v4.1 + v4.2.

If the intent was "P0 only, defer P1/P2 to v4.2" or "single Claude Code session, not single release", restructure on request.

## Dependency topology

```
Phase 0  Foundation: schemas + safe-fs primitives
   │
   ├──► Phase 1  Hooks (depends on 0.5 safe-fs)
   │
   ├──► Phase 2  Brownfield inventory skill (depends on 0.4 inventory schema)
   │       │
   │       ▼
   ├──► Phase 3  Bootstrap rewrite (calls Phase 2 skill, writes Phase 0 schema)
   │
   └──► Phase 4  Agent prompt updates (parallelizable; depends on Phase 0 schemas)
          │
          ▼
       Phase 5  Smoke + release (gates on Phases 0-4 complete)
```

Phase 4 is the widest fan-out — 11 tasks. Two file-collision pairs sequenced internally (4.1↔4.10 on `lead.md`; 4.4↔4.11 on `reviewer.md`); the other 7 are parallel-safe.

- All 15 brief items implemented and verified per phase tables above
- `scripts/validate.js` passes
- 5-step consumer-install smoke chain passes on both single-repo and multi-service fixtures
- No `appendFileSync` / `writeFileSync` calls remain in `hooks/scripts/`
- No `CONTRACT-NNN` references remain in consumer surface (`agents/`, `commands/`, `skills/`) or `CLAUDE.md` taxonomy
- `run-plan.md` authored and approved at bootstrap completion; multi-feature fixture passes end-to-end under `auto_mode: true` with reviewer `BLOCK` still pausing on synthetic violation
- Q1-Q5 resolved either in code or as `docs/BACKLOG.md` v4.1.1 entries
- `v4.1.0` tag pushed; `CHANGELOG.md` v4.1.0 section written
