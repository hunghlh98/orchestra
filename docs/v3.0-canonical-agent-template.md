# v3.0.0 — Canonical agent template (Batch 1 spec)

Companion to `docs/v3.0-prompt-tightening-brief.md`. Defines the prose template every agent in `agents/*.md` adopts in v3.0 Batch 1.

## Section sequence (mandatory, in order)

| # | Section | Tag | Notes |
|---|---|---|---|
| 1 | Identity paragraph | (none — body opens with this) | One sentence. Imperative. ≤25 words. |
| 2 | Tier | `## Tier` | Renamed from `## Tier discipline`. |
| 3 | Skills | `## Skills` | Bullet list. |
| 4 | Inputs | `## Inputs` | Single comma-separated line. |
| 5 | Outputs | `## Outputs` | Single comma-separated line. |
| 6 | Workflow | `## Workflow` | Numbered list, imperative. |
| 7 | Example | `<example>` wrapper | Required by `test-agents.js` (≥1). |

Optional, only when a load-bearing rule does not fit any of the above:

| # | Section | Tag | Notes |
|---|---|---|---|
| — | Frontmatter contract | `## Frontmatter contract` | Only when agent owns specific frontmatter writes. |
| — | Routing-taxonomy guard | `## Routing-taxonomy guard` | Only for `@product` and `@test`. |

Identity paragraph counts as section 1 even though no H2 — it's the first body paragraph after frontmatter.

## Per-section rules

### Identity paragraph

- Form: ``You are `@<name>`. <imperative, ≤20 words>.``
- Drop "You implement..." → "Implement...". Drop "You are responsible for..." → just state the role.
- No second sentence. No "per the TDD/CONTRACT authored by `@lead`" — that goes in Inputs.

### `## Tier`

- Line 1: `` `T-<X>` (<one-line characterization>). `tools:` frontmatter is authoritative; <validator> fails CI if violated. ``
- Then a bullet list. Each bullet ≤25 words, one rule. No "you should" / "you must" preamble — state the rule directly.
- No paragraph between line 1 and bullets.

### `## Skills`

- Bullet list only. No "You may invoke:" preamble.
- Form: `` - `<skill-name>` — <≤15-word purpose>. ``
- Conditional skills (e.g., language-specific) note the condition in a parenthetical: `(Java/Spring projects only)`.

### `## Inputs`

- Single comma-separated line. No prose paragraph.
- Form: ``<file pattern 1>, <file pattern 2>, ..., <generic surface like "source tree">.``

### `## Outputs`

- Same shape as Inputs. Negative outputs (`No verdict artifacts.`) get a separate sentence after the comma list.

### `## Workflow`

- Numbered list. Each step is imperative, ≤25 words.
- Sub-steps as nested bullets only when truly load-bearing (rare).
- No "Hand off to..." narration baked into other steps — make it the final numbered step.
- File patterns + status transitions stay verbatim (`Status` `pending` → `in_progress`, `S-TASKS-001.hash: TBD`, etc.) — these are load-bearing protocol, not narration.

### `<example>` block

- Form (already established in v2.2.2):

```
<example>
Context: <one-line scenario>.

1. <≤25-word step>
2. ...
</example>
```

- Drop the literal `Action steps:` header used in v2.2.2 — the numbered list IS the action steps.
- Single example per agent unless two genuinely distinct scenarios warrant separation. Default to one.

## Drop list (anti-patterns to remove)

| Pattern | Replace with |
|---|---|
| "You may invoke:" | (drop, go straight to bullets) |
| "You should..." / "You must..." | direct imperative ("Read X.", "Verify Y.") |
| "but remember:" / "however:" | (drop the preamble; state the rule) |
| "If the test contradicts CONTRACT, escalate to `@lead`; never modify CONTRACT yourself." | "If test contradicts CONTRACT, escalate to `@lead`." (the "never modify" is implied by tier) |
| "Action steps:" header inside `<example>` | (drop; the numbered list is self-evident) |
| Trailing rationale after a workflow step ("they will run the tests and grade the criteria") | (drop; downstream agent's role is its own concern) |

## Worked example — `agents/backend.md`

### BEFORE (current, 55 lines body)

```markdown
You are `@backend`. You implement server-side functionality (endpoints, services, persistence, background jobs) per the TDD and CONTRACT authored by `@lead`.

## Tier discipline

Tier T-C (implementer, no Bash). The `tools:` frontmatter is authoritative — `Bash` is excluded by design (`test-bash-strip.js` fails CI if added). Domain rules:

- Only `@evaluator` runs verdict-bearing tests. Never patch a failing test to make it green; if a test fails, the test or the contract is the truth — fix the code or escalate the contract.
- Do not interpret a green test run on your own as success — only `@evaluator`'s `verify/<NNN>-TEST.md` verdict counts.
- Do not touch frontend files.
- Do not modify upstream artifacts (`interfaces/<NNN>-CONTRACT.md`, `verify/<NNN>-TEST.md`) or release artifacts (`RUNBOOK-*.md`, `RELEASE-*.md`) — those are `@lead`/`@test`/`@ship`'s tier.
- New infrastructure needs (new DB, queue, third-party service) → escalate via `ESCALATE-ARCH-<id>.md` rather than plumbing silently.

## Skills

You may invoke:
- `karpathy-guidelines` — behavioral guidelines on assumptions, minimum surface, surgical edits, and verifiable goals. Apply during authoring; per-tier section emphasis is in the skill body.
- `java-source-intel` — when working on Java/Spring projects (P1; activated by `project-discovery` reporting `primary_language: java`).

## Inputs

interfaces/<NNN>-CONTRACT.md, design/<NNN>-TDD.md, plan/<NNN>-TASKS.md, and the current source tree. Existing rules under `rules/<lang>/` activate per file path.

## Outputs

Source files in the project's normal layout (e.g., `src/main/java/...`, `src/services/...`). Unit tests alongside the code or under `src/test/`. No verdict artifacts.

## Workflow

1. Read plan/<NNN>-TASKS.md to find your assigned tasks (`owner: @backend`). For each task you pick up, flip its row's `Status` from `pending` to `in_progress`, set `Updated by: @backend` and `Updated at: <ISO-8601>`, and re-stamp `S-TASKS-001.hash: TBD`. Update only your own row.
2. Read the upstream CONTRACT and TDD. Note `critical:` criteria — they're the bar to clear.
3. For Java work, invoke `java-source-intel` to surface caller graphs and `@Transactional` boundaries before editing.
4. Write the code. Match existing project conventions (formatter, imports, package structure). Run `rules/<lang>/coding-style.md` and `rules/<lang>/patterns.md` mentally as you work.
5. Write unit tests — but remember: you cannot run them. Trust the structure.
6. When the exit criterion is met, flip your row's `Status` from `in_progress` to `done` (re-stamp `S-TASKS-001.hash: TBD`). If you blocked on an upstream gap, write `ESCALATE-<id>.md` and leave Status as `in_progress` — the dispatcher will surface the ESCALATE on resume.
7. Commit your work via `@ship` or via `/orchestra commit`. Do not bypass.
8. Hand off to `@evaluator` (downstream task in plan/<NNN>-TASKS.md). They will run the tests and grade the criteria.

<example>
Context: `@evaluator`'s `verify/<NNN>-TSR.md` verdict shows a failing probe. The criterion is defined in `interfaces/<NNN>-CONTRACT.md`.
Action steps:
1. Read the failing probe + the criterion in CONTRACT. If the test contradicts CONTRACT, escalate to `@lead`; never modify CONTRACT yourself.
2. The test is the truth. Edit source to satisfy the criterion. Add unit tests covering boundary cases.
3. Apply per-language rules under `rules/<lang>/{coding-style, patterns, security, testing}.md`.
4. Flip your row's `Status` from `in_progress` to `done` (re-stamp `S-TASKS-001.hash: TBD`). Commit via `@ship` or `/orchestra commit`.
5. Hand back to `@evaluator` for re-grading.
</example>
```

### Audit and revisions

After user review, the first-draft AFTER had these deltas vs BEFORE — fixed in the revised AFTER above:

| # | Severity | Bug | First-draft AFTER | Revised AFTER |
|---|---|---|---|---|
| 1 | HIGH | Path glob inconsistency | `interfaces/*-CONTRACT.md`, `verify/*-TEST.md` | `interfaces/<NNN>-CONTRACT.md`, `verify/<NNN>-TEST.md` |
| 2 | HIGH | Lost section anchor prefix | `re-stamp hash: TBD` (Workflow 7) | `re-stamp S-TASKS-001.hash: TBD` |
| 3 | HIGH | Lost collision-prevention rule | (gone) | "Touch only your own row." appended to Workflow 2 |
| 4 | HIGH | Lost rule-activation mechanism | bare path glob `rules/<lang>/*.md` | `rules/<lang>/*.md` (auto-active per file path) |
| 5 | HIGH | Stale verdict-file ref kept by elision | (file ref dropped) | `verify/<NNN>-TSR.md verdict counts` (corrects v2.0 staleness) |
| 6 | MEDIUM | Lost author attribution | "per CONTRACT and TDD" | "per `@lead`'s CONTRACT and TDD" |
| 7 | MEDIUM | Lost skill timing | "Java work: invoke `java-source-intel`." | "Java work: invoke `java-source-intel` before editing." |

Defensibly dropped (covered elsewhere in the prompt or globally implicit):
- "those are `@lead`/`@test`/`@ship`'s tier" — tier ownership is established globally; per-rule attribution was rationale, not rule.
- "the dispatcher will surface the ESCALATE on resume" — informational; doesn't change agent behavior.
- "(downstream task in plan/<NNN>-TASKS.md)" — handoff mechanism; agent-to-agent convention is implicit across the codebase.
- "behavioral guidelines on" + "Apply during authoring" — meta-narration about karpathy-guidelines belongs in the skill body, not the agent.
- "P1; activated by project-discovery reporting primary_language: java" — activation mechanism; condition "Java/Spring projects only" carries the load.
- "(e.g., `src/main/java/...`, `src/services/...`)" — examples illustrating "project layout"; self-evident from the actual repo on inspection.

### Lessons for Batch 1 sweep (apply to remaining 7 agents)

1. **Path placeholders stay literal.** `<NNN>` (orchestra convention), not `*` (filesystem glob). Mixing forms teaches the LLM ambiguous syntax.
2. **Section anchors stay literal.** `S-TASKS-001.hash: TBD` is one token. Compressing to `hash: TBD` looks tidier but loses the lockfile-pairing reference.
3. **Stale path references get corrected, not preserved.** If BEFORE references a file that v2.0 renamed/repurposed, the v3.0 rewrite points at the correct file.
4. **Collision-prevention rules survive even at 4 words.** "Touch only your own row." is short but structural — it prevents row clobbering in shared TASKS.md edits.
5. **Activation hints survive even when path glob is present.** `(auto-active per file path)` is 5 words but tells the agent WHEN the rules engage.
6. **Author attribution survives in the identity sentence.** "per `@lead`'s CONTRACT" is 3 words longer than "per CONTRACT" but tells the agent who authored their inputs.
7. **Skill-invocation timing survives in workflow.** "before editing" is 2 words but specifies pre-condition, not just sequence position.

### Why the prediction missed

The `agents/backend.md` worked example caught 7 high-severity rule-loss bugs (see "Audit and revisions" above) on the FIRST draft. Fixing them shrunk the predicted -24% reduction to -16% on that single agent. The same audit pattern applied across the other 7 agents — every preserved rule cost lines back.

The prediction also didn't account for:
- **v1→v2 fold-leftover triage.** `evaluator.md`, `ship.md`, `reviewer.md` carried stale references to artifacts removed in v2.0 (`verify/<NNN>-CODE-REVIEW.md`, `verify/<NNN>-VERDICT.md`). Correcting them to TSR halves (`S-REV-VERDICT-001` + `S-REV-FINDINGS-001` / `S-EVAL-VERDICT-001` + `S-EVAL-TABLE-001`) added lines that the v2.0 baseline didn't yet have but should have.
- **Section-anchor preservation.** `S-TASKS-001.hash: TBD` is one token, but compressing to `hash: TBD` loses the lockfile-pairing reference. Long-form anchor strings cost lines.
- **Path placeholder discipline.** `<NNN>` (orchestra convention) vs `*` (filesystem glob). The v3.0 sweep made these consistent, which sometimes meant *expanding* terse `*` globs back to literal `<NNN>` placeholders.

### What did drop

Word and character count dropped meaningfully — line count is a poor proxy. Stylistic compression delivered:
- Imperative voice ("Implement...") replacing "You implement..."
- "Domain rules:" / "You may invoke:" preambles dropped
- Trailing rationale narration after workflow steps removed
- `Action steps:` header inside `<example>` dropped (numbered list is self-evident)
- Author attribution + skill timing kept inline (cheap, high signal)

The win is per-token efficiency, not file length.

### Lesson — for the next refactor planner

1. **Don't pre-commit to line-count reductions.** Predict word/char reduction; line count is noisy.
2. **Run the audit BEFORE picking targets.** The 7-bug audit on `backend.md` revealed 16% was the safe ceiling, not 24%. Apply audit to one heavy + one light agent first to calibrate.
3. **Accept growth in agents that absorb v1→v2 corrections.** Staleness leftovers are debt, and fixing them on the same sweep is correct — just don't pretend it's a reduction.
4. **Per-agent exceptions are not exceptions; they're the role's natural floor.** `lead.md` at 115 is right. Predicting 85 was wrong.
