# Orchestra plugin audit — 2026-05-21+

Running log of agreed findings from the file-by-file co-author audit.
Each bullet is a change driven by user-acknowledged review.
Open items + raw insights live in `.claude/temp/audit/audit.json` (gitignored).

## .claude-plugin/plugin.json — 2026-05-22

- **Add `repository` block.** `{ type: git, url: https://github.com/hunghlh98/orchestra.git }` so marketplace tooling and SCA tools have a canonical source URL; `homepage` alone is non-standard for that role.
- **Expand `keywords`.** Append `prd-frs-sad`, `spec-driven`, `dispatcher`, `c4-architecture`, `openapi` to widen marketplace search surface.
- **Document min Claude Code version.** Pin `Claude Code ≥ 2.0.42` under README Required section. Plugin schema has no `engines`/`requirements` field, so README is the only authoritative surface.
- **Drop README claim that `plugin.json` carries per-component arrays.** Claude Code auto-discovers `agents/`, `commands/`, `hooks/`, `skills/` from convention directories; defining them in `plugin.json` errors. To remove an agent or command, delete its file directly from the convention dir.

## .claude-plugin/marketplace.json — 2026-05-22

- **Pin plugin source to a release tag.** Add `source.ref: "v<semver>"` so consumers install a known-good revision instead of the rolling default branch. Closes the supply-chain window between merge-to-master and intentional release.
- **Mirror plugin.json metadata into the plugin entry.** `version`, `author`, `homepage`, `repository` (string form per marketplace schema), `license`, `keywords`. Marketplace UI renders its catalog row from `marketplace.json`, so missing fields show as a sparser-than-actual listing.
- **Add `owner.url`.** Maintainer link surfaces in the marketplace UI; `name` alone is unidentifying.
- **Extend the version-invariant from 3 files to 4.** `scripts/bump-version.js` gains a `marketplace` target kind that surgically rewrites `plugins[0].version` + `source.ref` in lockstep with the other three files. Phase-1 parse-check asserts plugin-entry shape so the surgical regex stays unambiguous.
- **Guard description / homepage / license / keywords parity with a CI test.** New `scripts/tests/marketplace-parity.test.js` (added to the `test` npm chain) compares `plugin.json` and `marketplace.json.plugins[0]` field-by-field. Drift is a build break, not a runtime surprise.

## .claude-plugin/.mcp.json — 2026-05-22

- **Move MCP server source to a consumer-surface dir.** `scripts/mcp-servers/` → `mcp-servers/` (plugin-root sibling to `agents/`, `commands/`, `hooks/`, `skills/`). Resolves the contradiction where shipped runtime code lived under a dir labelled "dev-only". `scripts/` is now truly never shipped. 11-file refactor across `.mcp.json`, `CLAUDE.md`, `.gitignore` allowlist, two test files (relative imports + `resolve()` paths), `manifests/install-modules.json`, `hooks/lib/README.md`, self-comment headers, and the server's own `PLUGIN_ROOT` / `import` path constants.
- **Declare `type: "stdio"` per server entry.** Explicit transport discriminator matches the MCP spec and makes future `http` / `sse` servers visually obvious in the manifest.
- **Document MCP launch's Node requirement in README.** `Node.js 18+` line under Required now states "on `$PATH`" and calls out silent ESM failure on older runtimes — pairs with the existing `package.json` `engines.node >=18`.
- **Two MCP servers stay separate by design.** `orchestra-utils` carries Gate-D write authority on `.orchestra/**` plus `amend_locked_artifact` / `relock_artifact`; `orchestra-probe` is strict read-only with response-body secret redaction (AWS/GitHub/JWT/RSA/Slack/Google/Bearer patterns) and SELECT-only `db_state`. Consolidating would let `@evaluator` reach write tools via a single MCP namespace; the boundary is intentional and recorded here so future refactors don't collapse it.

## commands/orchestra.md — 2026-05-22

- **Full rewrite, 512 → 271 lines.** Old dispatcher mixed strategy table, gate state machine, route resolution, payload algorithms, hook tables, runtime-flag matrix in one undifferentiated block. New shape: Invariants → Parse `$ARGUMENTS` → Strategy dispatch table S1-S9 → Preflight contract → Bootstrap → Run-plan + approval gate → Per-feature execution → Algorithm payloads → Ratify-spec on locked artifacts → Shared rules → Runtime hooks → Usage. Feature parity verified by the v4.0 4-subcommand fixture test (`spec-to-code`, `code-to-spec`, `<intent>` router, empty→usage; preflight contract; reverse_authoring_mode enum; 3-question floor; workspace_kind / scope_level enums; autonomy tags; coordination protocol).
- **`$ARGUMENTS` seeds Q1 restate-intent.** Router path used to ask Q1 verbatim ("what are you asking me to do?") even when the user typed `/orchestra add user authentication`. Q1 now reads the typed tail as the restate seed and asks the user to confirm-or-amend instead of re-typing.
- **Frontmatter pulls allowed-tools + argument-hint.** `allowed-tools: Read, Write, Edit, Bash, Agent, AskUserQuestion`; `argument-hint` enumerates the four entry shapes. Without `allowed-tools` Claude Code surfaces a permission prompt per first-time tool; without `argument-hint` the completion menu shows nothing.
- **Spring spec-correctness match rules moved to `skills/java-development`.** Old dispatcher hardcoded `@RequestBody` / `@PathVariable` / `@RequestParam` / `KafkaTemplate.send` / `@KafkaListener` / `RestTemplate.exchange` / `WebClient.bodyValue` match rules inline — dead weight on every load for non-Java projects. Now under `## Spec-correctness match rules (reverse-pass audit)` in the java-development skill; dispatcher cites abstractly.
- **C4 evidence + highlighted-copy + post-pass deliverable check moved to `agents/architect.md` + `skills/c4-architecture`.** Two-phase narrowing algorithm (phase A `service-shell-author` single-writer + phase B `feature-narrowing` DAG-rank parallel) lives in architect.md alongside spawn-brief templates. Arrow-evidence rule (REST controller / Kafka / outbound HTTP / `pom.xml`) + per-feature highlighted copy (UpdateElementStyle delta only, NO Container at L1) under `skills/c4-architecture` Step 8b + 8c.
