of the 11 streams in v4.0-brief §9. Names the surfaces touched (agents,
skills, hooks, schemas) and the exact deltas.

28 of them; this doc cites `§7.N` rather than re-justify. Code-level
implementation choices (regex bodies, exact YAML grammar, validator

## 3. Resolved /sc:sc-design-deferred decisions

The brief flags 3 items as deferred to design. Resolutions:

| § | Question | Resolution | Owning stream |
|---|---|---|---|
| 7.16 | Stage-1 `src/` block mechanism (per-stage tool scoping vs hook-level denial vs Read-path allowlist) | **Per-stage tool scoping at agent spawn.** `@test` Stage 1 spawns with a Read-allowlist that excludes `<consumer>/src/**`; Stage 2 spawns with the allowlist extended. Tool scoping prevents the agent from even *attempting* the read; hook-level denial would log noise after the fact and Read-path allowlist needs harness support not present on every install. | 8 |
| 7.17 | TSR evidence-split — keep raw evidence under `<project>/.orchestra/pipeline/<id>/tsr-evidence/`? | **NO split.** Verdict + findings + score table all live in `docs/<feature-id>/TSR-NNN.md`. Raw evaluator/reviewer transcripts are not artifacts — they're agent run logs and live in `events.jsonl`. Splitting introduces a second authority surface and risks "verdict says X but evidence file says Y" drift. | 1 |
| 9 stream 9 | `plantuml` render-enforcement (PostWrite hook on `*.puml` vs code-review failure on missing `.svg` vs `/orchestra render` subcommand) | **PostWrite hook on `*.puml`** (primary) **+ code-review failsafe** (defense-in-depth). PostWrite gives immediate render at write time; code-review catches cases where the hook was disabled. `/orchestra render` is rejected — it makes rendering an opt-in step that consumers will skip. | 9 |

## 4. Stream 1 — Foundation

**Wave A** (no deps; everything else depends on this).

**Requirements.**
- R1.1 — Runtime path moves from `<project>/.claude/.orchestra/` → `<project>/.orchestra/` (§5a).
- R1.2 — `<project>/docs/` becomes the stakeholder surface; per-feature artifacts under `docs/<feature-id>/`; ADRs under `docs/adr/` (§5b).
- R1.3 — `pipeline-artifact.schema.md` rewritten: drop lockfile-paired model; add `status: draft|locked`, `verdict: PASS|FAIL|APPROVED|REQUEST_CHANGES|pending`, `readers: <list>`, `sections: <map>` to frontmatter (§5f).
- R1.4 — `lockfile.schema.md`, `hash-stamper.js`, `section-hash.js`, `validate-drift.js` all deleted. Drift detection moves to `git diff` in CI.
- R1.5 — `pre-write-check.js` retooled: existing secrets matcher preserved; four new gates added.
- R1.6 — TSR evidence stays in TSR (per §3 above).

**Design.**

Frontmatter shape (illustrative):
```yaml
---
id: 001-PRD
type: PRD
status: draft               # draft | locked
verdict: pending            # PASS | FAIL | APPROVED | REQUEST_CHANGES | pending
readers: [@architect, @lead, @evaluator, @reviewer]
sections:                   # multi-writer coordination (TSR uses this most)
  S-VISION-001: {writer: "@product", status: locked}
  S-NFR-001:    {writer: "@product", status: in_progress}
---
```

`pre-write-check.js` four new gates:
- **Gate-A (frontmatter `status`).** Parse target file's existing frontmatter; if `status: locked` and incoming write isn't from the artifact's owning agent, exit 2.
- **Gate-B (sections lock).** When frontmatter has `sections:` map, parse incoming write to detect which `<a id="S-…">` sections it modifies (line-range intersection); reject writes to sections not in `pending|in_progress` for the calling writer. Trust-frontmatter vs diff-content choice deferred to `/sc:sc-implement` (§7.22).
- **Gate-C (readers allowlist).** Non-blocking. Stream-7 reporter aggregates warnings (§7.24).
- **Gate-D (§7.28 src/ purity).** Match the cite denylist regex (`PRD §`, `FRS §`, `TDD §`, `CONTRACT §`, `TSR §`, `ADR-NNNN §`, `FR-N`, `AC-N`, `C-N`, `NFR-N`, `S-XXX-NNN`, `openapi.yaml#/paths/`) against incoming writes whose target path matches `<consumer>/src/**` or language equivalents. Exit 2 on any hit.

Migration of in-flight v3.x consumers: NONE. v3.x is EOL per brief §9.

**Files touched.**
- WRITE: `schemas/pipeline-artifact.schema.md` (full rewrite); `hooks/scripts/pre-write-check.js` (rewrite, secrets matcher preserved).
- DELETE: `schemas/lockfile.schema.md`; `hooks/scripts/hash-stamper.js`; `hooks/lib/section-hash.js`; `scripts/validate-drift.js`.
- TOUCH: `commands/orchestra.md`, every `agents/*.md`, every `skills/*/SKILL.md` that names a `<project>/.claude/.orchestra/` path.

**Tasks.**
- T1.1 — Draft new `pipeline-artifact.schema.md` (frontmatter shape, §5b folder map, body grammar without lockfile sections).
- T1.2 — Rewrite `pre-write-check.js`: preserve secrets matcher; add 4 new gates per design above. Unit tests cover each gate.
- T1.3 — Delete `lockfile.schema.md`, `hash-stamper.js`, `section-hash.js`, `validate-drift.js`. Update `validate.js` to drop lockfile predicates (`validateLockfilePresence`, `validateLockfileGrammar`, `validateDiagramHashes`, `validateFoldCorrectness`'s lockfile branch).
- T1.4 — Sweep `<project>/.claude/.orchestra/` → `<project>/.orchestra/` across consumer surface. Done when `grep -r ".claude/.orchestra" agents/ skills/ commands/ schemas/ hooks/` returns zero.
- T1.5 — Document `status:`, `verdict:`, `readers:`, `sections:` examples + validation rules in the new schema. Document the §7.28 src/ denylist alongside.

## 5. Stream 2 — Entry flow

**Wave B** (depends on Stream 1).

**Requirements.**
- R2.1 — `/orchestra` (no args) detects mode (greenfield vs brownfield).
- R2.2 — AskUserQuestion fires only when answers can't be inferred from prompt or repo state.
- R2.3 — Chain-rigor presets (Full | Standard | Light) drive layer election (§4).

**Design.**
- Mode detection: empty repo (no `src/`, no `package.json`/`pom.xml`/`go.mod`) → greenfield; else brownfield. Ambiguous (e.g., `docs/` exists but no source) → ask.
- Decision tree lives in `commands/orchestra.md` body. Each branch is a guarded AskUserQuestion call.
- Answer cache: `<project>/.orchestra/local.yaml` so re-runs don't re-prompt.

**Files touched.**

## 11. Stream 8 — Performance

**Wave D** (depends on Stream 7).

**Requirements.**
- R8.1 — `@backend ‖ @frontend ‖ @test (Stage 1)` execute in parallel once openapi is locked (§2.ter).
- R8.2 — `@test` Stage 1 is **spec-bound**: cannot read `<consumer>/src/**`. Mechanism: per-stage tool scoping at agent spawn (per §3 above).
- R8.3 — `@backend` supports within-agent parallelism for large impl tasks (BL-0033).
- R8.4 — Stage-1 unwritability ⇒ `DEADLOCK-<id>.md` back to @lead.

**Design.**
- @lead spawn pattern: when openapi is locked, fan out to @backend + @frontend + @test (Stage 1) with parallel Agent calls in one message. Each spawn carries scoped Read allowlist. @test Stage 1's allowlist excludes `src/**` and `<consumer>/src/**`.
- Within-agent parallelism: @backend prompt teaches the agent to use Agent + scoped sub-runs when the task graph in TASKS-NNN.md has parallel-eligible nodes. Prompt discipline only — no harness change.
- @test Stage 1 deadlock path: when the agent cannot author a test for an FRS rule because openapi is silent, write `DEADLOCK-<id>.md` referencing the missing spec element. @lead picks up and asks @architect/self to amend openapi.

**Files touched.**
- WRITE: `agents/lead.md` (parallel-fan-out spawn pattern + DEADLOCK pickup); `agents/test.md` (two-stage prompt; sources allowlist by stage; DEADLOCK trigger); `agents/backend.md` (within-agent parallelism prompt); `agents/frontend.md` (parallel-with-others note).

**Tasks.**
- T8.1 — Update `agents/lead.md` spawn-pattern: openapi-locked → fan out (@backend ‖ @frontend ‖ @test Stage 1) in a single Agent-tool-call message; each spawn carries scoped sources.
- T8.2 — Author `agents/test.md` Stage 1 prompt: sources = openapi/asyncapi + PRD + FRS only; output = TSR-NNN.md §test-plan + black-box test code; on spec gap → DEADLOCK-<id>.md.
- T8.3 — Author `agents/test.md` Stage 2 prompt: sources = Stage 1 sources + `src/**`; output = test execution + impl-aware additions per §NFR.
- T8.4 — Update `agents/backend.md` with BL-0033 within-agent parallelism prompt (split large impl tasks into N parallel sub-runs via Agent calls).
- T8.5 — Add DEADLOCK pickup logic to `agents/lead.md`: when `<project>/.orchestra/pipeline/<id>/DEADLOCK-*.md` appears, route to @architect or @lead-self for openapi gaps.
