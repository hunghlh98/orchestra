# v3.0.0 — Prompt + Artifact Tightening Brief

## Decision summary

| Field | Value |
|---|---|
| Version | v3.0.0 (MAJOR, breaking) |
| Authorized | 2026-05-07 via `/sc:sc-brainstorm` session |
| Supersedes | `project_orchestra-v2-release-window` memory (v2.* window closed) |
| Constraint freedom | Anchor IDs, frontmatter shapes, artifact body grammar, H2 names — all unfrozen |

## Goals

1. Reduce consumer-surface token cost — 23 files, ~3000 lines.
2. Convert narrative prose to markdown procedural steps wherever a procedure is implied.
3. Strip remaining domain priors (URL-shortener / transfer / toast / SQLite-WAL DNA from v1).
4. Preserve every load-bearing rule. No nuance lost to compression.
5. Standardize per-tier section structure (agents share one H2 sequence; skills share another).

## Scope

**In**
- `agents/*.md` × 8 — Batch 1
- `skills/*/SKILL.md` × 14 — Batch 2 (heavy: c4-architecture 404, plantuml 304, write-contract 203)
- `commands/orchestra.md` — Batch 3
- `schemas/pipeline-artifact.schema.md` body grammar per artifact type — Batch 3

**Out**
- `docs/*` (dev-only)
- `hooks/scripts/*.js`, `hooks/lib/*.js`, `scripts/*.js` (code, not prose)
- `rules/<lang>/*.md` (defer)
- `schemas/*.schema.json` (frontmatter shape stays JSON-schema-stable; only the markdown narrative changes)

## SemVer rationale

MAJOR per https://semver.org/spec/v2.0.0.html:
- Anchor renaming → breaks existing pipelines under `.claude/.orchestra/pipeline/<id>/`.
- Body grammar restructure → breaks hash-stamper lockfile pairing.
- Artifact section consolidation → consumer pipelines fail v3 validators.
- No back-compat shim. Migration = "complete or abandon v2 pipelines, then upgrade."

## Batched delivery plan

### Batch 1 — Agents (8 files, ~616 lines)

1. Establish prompt template: `Tier discipline / Skills / Inputs / Outputs / Workflow / Example`.
2. Each section's body uses numbered steps where procedural, bullets where checklist, prose only when a rule needs sentence framing.
3. Validators that must stay green: `test-agents.js`, `test-bash-strip.js`, `validate.js`, `validate-drift.js`.
4. **Pause**: user runs interactive smoke (greenfield bootstrap → first feature pipeline) and reports back.

### Batch 2 — Skills (14 files, ~2000+ lines)

1. Standardize skill template: `Trigger / Inputs / Steps / Outputs / Failure modes`.
2. Bulk reduction: c4-architecture 404→~150, plantuml 304→~120, write-contract 203→~100.
3. Validators: `validate.js`, `test-removability.js`.
4. **Pause**: user runs smoke + interactive feedback before Batch 3.

### Batch 3 — Command + schema (`commands/orchestra.md` 265 lines + body grammar)

1. `commands/orchestra.md` shrinks; subcommand routing stays explicit but framed as numbered steps.
2. `schemas/pipeline-artifact.schema.md` gets renamed anchor IDs + clarified shape per artifact.
3. Schema changes ripple to Batch-1 agents — re-validate Batch 1 after Batch 3 schema settles.
4. Validators: full `npm test` chain + 5-step install smoke chain.
5. **Pause + final smoke**: full end-to-end on a fresh `/tmp/orchestra-smoke-10/`.

## Risks

- **R1 — Rule loss in compression.** Mitigation: per-batch user smoke + interactive feedback.
- **R2 — Anchor renaming ripple.** Schema is Batch 3 (last); Batch-1 agents updated to consume new anchors after schema settles.
- **R3 — Migration friction for existing consumers.** Hard break, no shim. Mitigation: clear MAJOR signal in CHANGELOG + migration paragraph in v3.0.0 release notes.

## Migration (v3.0.0 CHANGELOG content)

1. Pre-upgrade: complete or abandon all active pipelines under `.claude/.orchestra/pipeline/<id>/`.
2. Upgrade: `claude plugin update orchestra` (or reinstall via marketplace).
3. Post-upgrade: start new pipelines via `/orchestra <intent>`. Old artifacts on disk remain readable but won't pass v3 validators.

## Open questions (deferred to design phase, not blocking now)

- Anchor naming convention: keep `S-NAME-001` shape, drop the `-001` suffix, or drop the `S-` prefix entirely?
- `<example>` block shape: keep numbered Action steps (v2.2.2 shape), or augment with an `Anti-pattern:` sub-block?
- `test-agents.js` `<example>` count threshold: relax from ≥1 to ≥0 (drop the wrapper) or keep ≥1?
